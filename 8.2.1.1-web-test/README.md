# Проверочная работа 8.2.1.1 — веб-приложение

Тема: перевод натуральных чисел из десятичной системы счисления в двоичную, восьмеричную, шестнадцатеричную и обратно.

Все ученики открывают **одну общую ссылку**, нажимают «Начать» и автоматически получают один из 15 вариантов. Имя, логин и другие личные данные не запрашиваются.

## Как устроено

| Часть | Файлы | Где работает |
|---|---|---|
| Страница ученика | `index.html`, `app.js`, `common.js`, `variants.js`, `style.css`, `config.js` | статический сайт (GitHub Pages или любой хостинг) |
| Страница учителя | `teacher.html` | там же |
| Выдача вариантов | `server/Code.gs` | Google Apps Script (веб-приложение) |

**Что хранится на сервере (Apps Script):** только номера выданных вариантов, привязанные к случайным техническим идентификаторам сессий, и номер «раунда» (меняется при сбросе). Ответы, баллы и какие-либо данные учеников на сервер **не отправляются**.

**Что хранится в браузере ученика (localStorage):** ход работы, ответы и таймеры — чтобы после случайного обновления страницы работу можно было продолжить.

### Работа

- 15 вариантов одинаковой структуры, по 10 открытых заданий (ответ вводится с клавиатуры, проверка автоматическая):

  | № | Тип задания | Диапазон чисел |
  |---|---|---|
  | 1 | 10 → 2 | 20–63 |
  | 2 | 2 → 10 | 20–63 (5–6 двоичных разрядов) |
  | 3 | 10 → 8 | 70–400 |
  | 4 | 8 → 10 | 10–63 (двузначные восьмеричные) |
  | 5 | 10 → 16 | 30–159, в записи есть буква A–F |
  | 6 | 16 → 10 | 26–255, в записи есть буква A–F |
  | 7 | 10 → 2 | 64–200 |
  | 8 | 2 → 10 | 64–255 (7–8 разрядов) |
  | 9 | 8 → 10 | 64–400 (трёхзначные восьмеричные) |
  | 10 | 10 → 16 | 160–255, есть буква A–F |

  Итого в каждом варианте 5 заданий «из десятичной» и 5 «в десятичную». Числа не повторяются ни внутри варианта, ни между вариантами в одной позиции; «слишком удобные» числа (111111₂, FF₁₆, 200₈ и т. п.) исключены.
- Ответ принимается без учёта регистра, пробелов и ведущих нулей (`5c` = `5C`, `0101` = `101`).
- Общий таймер — 15 минут, таймер задания — 1 минута; оба видны постоянно.
- Время задания истекло → задание неправильное, открывается следующее.
- «Пропустить» → задание пока засчитано как неправильное; после 10-го задания можно вернуться к пропущенным (на каждое снова 1 минута) или завершить работу.
- Через 15 минут работа завершается автоматически, оставшиеся задания — неправильные.
- В конце: крупно «N / 10 баллов», число правильных ответов и отчёт по каждому заданию с правильным ответом.
- Выход из полноэкранного режима, переключение на другую вкладку, окно или приложение → работа **сразу завершается** с пометкой причины.

## 1. Запуск на своём компьютере (проверка, демо-режим)

Нужен только Python 3 (или любой другой простой веб-сервер):

```bash
cd 8.2.1.1-web-test
python3 -m http.server 8000
```

Откройте <http://localhost:8000/>. Пока в `config.js` пустая ссылка `API_URL`, работает **демо-режим**: варианты выдаются в пределах одного браузера (сброс — на странице `teacher.html`, PIN не проверяется). Для урока демо-режим не подходит — подключите сервер (шаг 2).

Проверка вариантов: `node tools/check-variants.js`. Новый набор чисел: измените `SEED` в `tools/generate-variants.js` и выполните `node tools/generate-variants.js`.

## 2. Сервер выдачи вариантов (Google Apps Script)

1. Откройте <https://script.google.com> → **Новый проект**.
2. Вставьте содержимое `server/Code.gs`. **Замените PIN** в строке `var TEACHER_PIN = '8211';` на свой. Сохраните.
3. **Начать развертывание → Новое развертывание → Тип: Веб-приложение**:
   - «Запуск от имени»: **Я**;
   - «У кого есть доступ»: **Все** (Anyone) — тогда ученикам не нужен Google-аккаунт и вход.
4. Разрешите доступ, скопируйте ссылку (оканчивается на `/exec`).
5. Вставьте её в `config.js`: `window.API_URL = 'https://script.google.com/macros/s/…/exec';`

При изменении `Code.gs` выберите **Управление развертываниями → Изменить → Версия: новая**, чтобы ссылка осталась прежней.

## 3. Публикация страницы (GitHub Pages)

1. Закоммитьте изменения `config.js` в ветку `main` репозитория.
2. На GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
3. Через 1–2 минуты работа будет доступна по адресу
   `https://<ваш-логин>.github.io/<репозиторий>/8.2.1.1-web-test/`
   (для этого репозитория: `https://raziyanis.github.io/fizmat/8.2.1.1-web-test/`).
   Страница учителя: тот же адрес + `teacher.html`.

GitHub Pages для приватного репозитория доступен только на платных тарифах; для бесплатного аккаунта репозиторий должен быть публичным. Подойдёт и любой другой статический хостинг (например, Netlify: перетащите папку `8.2.1.1-web-test` на <https://app.netlify.com/drop>).

Сайт должен открываться по **https** — иначе браузеры могут не разрешить полноэкранный режим.

## 4. На уроке

1. **Перед классом** откройте `teacher.html`, введите PIN → **Сбросить выданные варианты**. (Или в редакторе Apps Script выполните функцию `resetVariants`.) На устройствах, где работа уже была завершена, после сброса снова появится кнопка «Начать».
2. Дайте ученикам ссылку (QR-код на доске, Classroom и т. п.).
3. На странице учителя видно, сколько вариантов выдано. Если 16-й ученик нажмёт «Начать», он увидит «Все 15 вариантов уже выданы. Обратитесь к учителю».
4. Ключи ко всем вариантам: `teacher.html` → **Показать ключи** (можно распечатать).
5. Баллы ученик показывает учителю на итоговом экране — на сервер они не отправляются.

Если ученик обновит страницу, работа восстановится с тем же вариантом и таймерами (время продолжает идти); для возврата в полноэкранный режим он нажимает «Продолжить».

## 5. Что может и чего не может веб-страница

Страница в обычном браузере **не может**:
- убрать крестик закрытия окна или вкладки браузера;
- заблокировать Alt+F4, Alt+Tab, клавишу Windows, Ctrl+Alt+Del, жесты и кнопки телефона;
- помешать закрыть браузер или выключить устройство;
- запретить выход из полноэкранного режима (Esc всегда работает; в Chrome/Edge приложение перехватывает Esc, поэтому для выхода нужно удерживать его, а ученик видит предупреждение).

Что делает приложение:
- включает полноэкранный режим по кнопке «Начать» (браузеры разрешают это только после нажатия пользователя, поэтому сразу при открытии ссылки — нельзя);
- **сразу завершает работу**, если ученик вышел из полноэкранного режима, переключился на другую вкладку, окно или приложение;
- при попытке закрыть или обновить вкладку показывает стандартный вопрос браузера «Покинуть сайт?»;
- блокирует кнопку «Назад», контекстное меню и сочетания Ctrl+R/P/S/F/T/N/W/L, F5, F11 — там, где браузер это позволяет (часть сочетаний страница перехватить не может);
- не содержит ссылок на другие страницы и кнопок выхода.

Ограничения: на iPhone (Safari) полноэкранный режим для страниц не поддерживается — там работает только контроль переключения вкладок и приложений. Технически подготовленный ученик может открыть инструменты разработчика; на школьных устройствах их можно отключить политиками (см. ниже).

## 6. Режим киоска на школьных устройствах

Если нужно действительно не дать закрыть окно и переключиться на другие программы, запускайте работу в режиме киоска. **Только в этом режиме** ограничения действуют на уровне браузера или операционной системы.

### Windows: Chrome или Edge с ключом `--kiosk` (быстро, но частично)

Создайте ярлык:

```
"C:\Program Files\Google\Chrome\Application\chrome.exe" --kiosk --incognito --no-first-run "https://raziyanis.github.io/fizmat/8.2.1.1-web-test/"
```

(для Edge: `msedge.exe --kiosk "…ссылка…" --edge-kiosk-type=fullscreen --no-first-run`).

Работает только в киоске: нет адресной строки, вкладок, кнопок окна и крестика; страницу нельзя свернуть через F11.
**Не блокируется**: Alt+F4 закрывает браузер, Alt+Tab и клавиша Windows переключают программы, Ctrl+Alt+Del. Приложение всё равно заметит уход из окна и завершит работу. Перед запуском закройте все другие окна этого браузера — иначе ключ `--kiosk` может не сработать.

### Windows 10/11 Pro/Education: «Назначенный доступ» (Assigned Access) с Microsoft Edge (надёжно)

**Параметры → Учётные записи → Другие пользователи → Настроить киоск**: создайте локальную учётную запись для работы, приложение — **Microsoft Edge**, режим «Цифровой знак / интерактивный дисплей», адрес — ссылка на работу.
Работает только в этом режиме: под этой учётной записью запускается только Edge на весь экран, другие программы, рабочий стол и Alt+Tab недоступны. Выйти можно через Ctrl+Alt+Del (это нельзя отключить ни в одной системе) — выход из учётной записи закроет работу.

### Любые компьютеры Windows/macOS: Safe Exam Browser (надёжно, бесплатно)

<https://safeexambrowser.org>. В конфигурации укажите стартовую ссылку на работу и пароль выхода.
Работает только в SEB: блокирует переключение программ, Alt+F4, Alt+Tab, диспетчер задач, печать экрана; выход — только по паролю учителя.

### Chromebook под управлением школы (Google Admin)

Администратор может настроить **киоск-приложение/веб-киоск** с этой ссылкой либо запретить инструменты разработчика и переключение (политики `DeveloperToolsAvailability`, `URLAllowlist`/`URLBlocklist`). Работает только на управляемых устройствах.

### Телефоны и планшеты

- Android: **Закрепление приложения** (Настройки → Безопасность → Закрепление приложений) — ученик не выйдет из браузера без PIN/жеста разблокировки.
- iPhone/iPad: **Гид-доступ** (Настройки → Универсальный доступ → Гид-доступ) — блокирует выход из Safari до ввода кода.

## Файлы

- `index.html`, `app.js` — страница ученика (варианты, таймеры, проверка, защита от выхода, восстановление после обновления).
- `common.js` — формулировки заданий, проверка ответа, обращение к серверу / демо-режим.
- `variants.js` — 15 вариантов (генерируется `tools/generate-variants.js`).
- `teacher.html` — статистика выдачи, сброс, ключи.
- `server/Code.gs` — Google Apps Script: выдача неповторяющихся вариантов и сброс.
- `tools/check-variants.js` — проверка вариантов.
